# Security reporting — Pectrium

Pectrium takes potential security issues seriously, but this document **does not claim a staffed security team, response SLA, bug bounty, or guaranteed remediation timeline**.

## Reporting a vulnerability

**Private reporting channel: founder confirmation required.** Before this process can be relied upon publicly, the repository owner must confirm and enable GitHub private vulnerability reporting (where available), or approve another private contact channel.

If GitHub's **Report a vulnerability** option is enabled under the repository Security tab, use it to share the affected component, reproduction steps, potential impact, and suggested mitigation. If that option is not enabled, do **not** post exploit details, credentials, private data, or active vulnerabilities in public issues. Request a private reporting channel from the repository owner through an already verified contact method.

## Scope and responsible handling

This repository includes a corporate website, Flow execution engine, and local-only starter tooling. Their presence does not establish that any product is production-ready or offered as a hosted service.

- Do not include real credentials or sensitive user data in reports, examples, commits, or logs.
- Do not perform intrusive testing against production or third-party systems without authorization.
- Maintainers should privately triage, reproduce, prioritize, and coordinate disclosure after a report is received.
- Support and disclosure procedures remain subject to founder approval.

**Founder confirmation needed:** the preferred private vulnerability-reporting channel, designated maintainer responsibility, and any future published response policy.
